# Public API benchmark methodology — 1.0 draft

Prepared 2026-09-21, before any benchmark requests. **Pilot only; not locked and no results claimed.** This is a reproducible two-workload study, not an uptime measurement or a statement about every Apify Actor. The operator must complete `READINESS.md`, preserve the pilot separately, and freeze the full configuration and inputs before measuring.

## Workloads and usability

1. `youtube-caption`: one public YouTube video URL → existing English caption text. Use manually prechecked English-captioned videos with diverse durations and publishers. No AI transcription, translation, playlists, feed enumeration or generated summaries. A usable response must contain non-whitespace caption text and a matching returned video ID/URL where the provider exposes it. SocialKit returns the request URL, which binds the response to the requested operation but does **not** independently prove scraped identity; disclose `request-bound` identity and manually compare caption excerpts to the source in QA. SocialKit does not return language/source fields; English and caption origin need source/response QA. Never silently assume these fields are verified. Missing segment timestamps are optional completeness data.
2. `instagram-reel`: one public `/reel/<shortcode>/` URL → metadata for that exact Reel. Required: matching shortcode, nonempty author username, a valid publication timestamp, nonnegative likes and comments. A caption is optional (an empty caption can be valid), as are views, shares, duration and thumbnail. **Views are optional for all providers.** SocialKit uses `requireViews=false`. Missing/hidden/negative metrics stay `null`, never zero. Numeric Instagram media IDs are not comparable to shortcodes. Do not substitute profile feeds for this job.

Any HTTP 200 with empty text, wrong identity or missing required metadata is unusable. Keep each failure in the planned denominator. Internal monitor traffic and customer failure logs are excluded from sample selection and public evidence.

Record provider cache indicators when exposed and do not call the comparison universally uncached. Repeat input subset separately after the primary sample; repeats never inflate its denominator.

## Pilot, fixed sample and run limits

Pilot: 2–3 independently chosen URLs per workload and all three providers. Preflight validates all credentials without printing them. Operator approval cap: **$5 across the sprint**, existing balances only; no purchase or automatic refill. `budget.maxUsd` is the remaining cap for each invocation, not a fresh $5 allowance. Deduct every previous pilot/run reservation (including uncertain failures) before subsequent invocations. The runner reserves worst-case cost for each paid attempt before sending it; it never releases reservations merely because a request timed out. `budget.maxAttempts` and per-provider credit caps also apply.

Full run: 20–30 unique public URLs per workload, with 3 separately labelled repeats per workload and the same three providers. Inputs must have source/selection notes and precheck dates; use a mixture of publishers and durations, not just provider examples. Freeze exact files, SHA-256 hashes, runner commit, provider plan/cost assumptions, and manual pilot findings. A changed normalization, Actor or selection rule requires a new methodology version and new run; never adjust after seeing a winner. No full run may start with draft status or missing prerequisites.

Attempt deadline: 120 seconds from immediately before submission through body parsing and usability validation, including all polling and dataset retrieval. Apify receives a shorter server timeout of 110 seconds, `restartOnError=false`, `maxItems=1`, and an explicit `maxTotalChargeUsd` for every run. Poll every 2 seconds, bounded to the attempt deadline and a maximum HTTP request count. Best-effort abort and final charge reconciliation after timeout are recorded separately; they do not extend usable latency. One retry after 2 seconds is allowed only for network errors, timeouts, HTTP 408/429/5xx or transient Actor failures. No retry for wrong identity, empty text, authorization, schema or permanent unavailable errors. First attempt and retry remain separate rows. End-to-end eventual-success latency includes the failed first attempt and retry delay. Budget/deadline-stopped jobs remain explicit `not-run-*` outcomes; they are not provider failures and bar a complete-sample headline.

## Cost policy

Credits, requests and usable results are separate units. Keep `actualCredits` from SocialKit `X-Credits-Used`/pricing-version headers and ScrapeCreators `credits_charged`; missing charge evidence is `null`, even on failures. Pin per-credit USD to the tested account's plan/cadence/allowance and write its source in config. Converted credit USD is **modeled**, not an invoice or cash total. SocialKit cohort is recorded from response evidence; no source constant or advertised plan proves the account's active cohort. The two selected SocialKit operations are currently one-credit operations; verify this in the pilot. Reserve an explicit conservative maximum per attempt.

Apify actual `usageTotalUsd` is captured only from terminal run metadata; charge events and pricing metadata are kept privately. If missing, report cost unknown and keep the full reservation. The API `maxTotalChargeUsd` plus server timeout bounds a run; the local runner conservatively reserves that cap. Actor/API docs differ on whether that parameter covers every pricing model; therefore preflight accepts these selected Actors only after authenticated pricing confirms `PAY_PER_EVENT`, a compatible minimum cap, and no recurring/rental charge. No claim that a local timeout cancels remote spending. Pending reconciliation prevents publication. Report observed charges, modeled credit conversion, unknown charges and conservative reservation separately, including unsuccessful attempts. No known-cost subtotal may be presented as complete total when costs are unknown.

## Evidence and analysis

Private mode-0700 run directory: manifest, a durable attempt-start journal, sanitized response bodies/allowlisted headers for each HTTP exchange, normalized attempts/outcomes JSON and CSV. Files are mode 0600 and never tracked. Credentials, authorization/cookie headers and signed URL query strings are redacted even privately. Interrupted runs retain start records; do not re-run an uncertain attempt blindly. Resolve Apify run IDs/charges from private evidence first. A public export uses a strict allowlist: supplied public input URLs, labels, timings, outcome categories, identity assurance, completeness flags, numeric charges and explicit assumptions. It excludes transcript/caption text, raw response URLs, headers, run IDs and account IDs.

Analysis is deterministic and reproducible: per workload/provider, planned/attempted/usable counts, first-attempt success, eventual success, missing fields, failure categories, actual credits, modeled USD, Apify actual USD, unknown-cost count. Median is the ordinary sample median; p90 uses nearest rank and is descriptive only (20–30 inputs is a small sample). Latency is reported **only among usable outcomes**, alongside failures/timeouts; never replace failures with zero or compare survivor latency without its denominator. Separate primary/repeat samples. Include period, plan, single-client geography, cache limitations, identity/language QA limits and cases a competitor does better. No universal fastest/most reliable/uptime claims.

Manual QA before publication: inspect every failure and empty/missing-required-field case, three successes per workload/provider, and each provider's slowest success. For captions verify source identity, English and existing-caption origin using source page captions and excerpts. For Reels verify shortcode/author/timestamp and nullable metrics. Save reviewer, timestamps, sample IDs, observations and decisions in `qa.json`; do not modify raw measurements. Publish the existing comparison article and downloadable evidence together only after complete sample accounting and QA.
